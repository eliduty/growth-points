## Context

家长端统计页面当前采用双页面设计（概览页 `/parent` + 详情页 `/parent/stats/[childId]`），但原型 HTML `parent-stats.html` 采用单页面设计（孩子卡片横向滑动 + 记录折叠分组），两者结构不一致。

核心差异点：
- 页面结构：原型单页面 vs 实现双页面
- 撤销交互：原型点击按钮 vs 实现长按卡片
- 卡片布局：原型横向滑动 vs 实现垂直列表
- 原型缺少详情页设计

经 UX 分析讨论，确认保持双页面设计更合理，原型需更新以匹配实现。

## Goals / Non-Goals

**Goals:**
- 统一原型与实现，消除设计文档与代码的差异
- 撤销操作改为点击按钮，交互更直观
- 原型新增详情页设计，完整展示双页面结构
- 详情页标题明确，移除冗余返回按钮

**Non-Goals:**
- 不改变页面结构（保持双页面）
- 不改变奖励按钮位置（保持在详情页）
- 不修改 API 或数据结构

## Decisions

### 决策 1：保持双页面设计

**理由：**
- 概览页简洁，只显示核心数据（完成数、积分）
- 详情页聚焦管理操作（奖励、撤销）
- 渐进披露信息，符合"概览 → 详情"模式
- 家长多数场景只需查看概览，少数情况才进入详情

**替代方案：单页面设计**
- 一屏展示所有信息，信息过载
- 多孩子时页面过长，需滚动回顶部切换

### 决策 2：撤销改为点击按钮

**理由：**
- 按钮可见，发现性高
- 点击比长按更直接
- 避免用户不知道可撤销

**替代方案：长按卡片**
- 需要提示说明，发现性低
- 800ms 等待时间较长
- 隐藏操作增加认知负担

### 决策 3：详情页标题使用"完成记录"

**理由：**
- 简洁明确，表达页面内容
- 不随孩子名字变化，代码简单
- 与概览页"统计"层级区分清晰

### 决策 4：移除详情页手动返回按钮

**理由：**
- TopNavbar 已有返回按钮
- 重复按钮浪费空间，视觉冗余

## Risks / Trade-offs

**风险：原型更新后需持续维护**
- 需确保原型与实现同步更新
- 后续功能迭代需同时修改原型和代码

**权衡：撤销按钮占用记录卡片空间**
- 记录卡片右侧新增按钮，信息密度略增
- 但交互直观性提升，收益大于成本
