## Context

当前任务系统所有任务每天都显示给孩子，无法支持特定日期的任务安排。家长创建任务后无法指定哪些日期任务生效，孩子无法区分"今天要做"和"其他时间做"的任务。

约束：
- SQLite 数据库，字符串字段存储日期列表
- 项目尚未上线，无需向后兼容迁移
- 孩子端主要为移动端使用，界面需简洁

## Goals / Non-Goals

**Goals:**
- 家长能为任务设置可用日期（周一至周日）
- 孩子能清晰区分"今日待办"和"其他时间"的任务
- 孩子能看到完整的任务清单，有全局认知
- 不可用日期的任务有明确的交互限制

**Non-Goals:**
- 周视图功能（其他时间区域已满足需求）
- 复杂的日期规则（如"每隔周二"、"每月第一周"）
- 任务提前完成功能（严格限制只能在指定日期完成）

## Decisions

### 1. 数据存储：逗号分隔字符串

**选择**: `availableDays: String?` 存储如 `"1,3,5"`

**理由**:
- SQLite 字符串存储简单
- 日期数量有限（最多7个），无需 JSON 数组
- 前端/后端处理都简单：`days?.split(',').map(Number)`

**备选方案**:
- JSON 数组 `"["1","3","5"]"` — 解析开销，SQLite 不原生支持
- 多表关联 — 过度设计，日期数量固定

### 2. null 语义：草稿/待定状态

**选择**: `null` = 任务未安排日期，孩子端不显示

**理由**:
- 家长可以先创建任务，后续确定安排
- 区分"已生效"和"待配置"状态
- 现有任务保持 null，由家长手动设置

**备选方案**:
- `null` = 每天可用 — 无法区分"待安排"状态
- 新增 `status` 字段 — 语义重复，`availableDays` 已能表达

### 3. 孩子端分组：三层结构

**选择**: 今日待办 / 已完成 / 其他时间

**理由**:
- 焦点清晰：今日待办只显示未完成
- 成就感：完成后移到已完成区域
- 全局认知：其他时间让孩子知道本周还有任务

**备选方案**:
- 两层（今天可做 + 已完成）— 可做区域包含已完成，焦点分散
- 两层（待完成 + 其他时间）— 缺少完成后的成就感展示

### 4. 交互限制：严格限制

**选择**: 不可用任务点击提示"这个任务周三才能做哦"，不允许完成

**理由**:
- 规则简单，孩子容易理解
- 符合家长设定意图
- 数据逻辑清晰

**备选方案**:
- 允许提前完成 — 规则复杂，可能混乱

## Risks / Trade-offs

**风险**: 家长忘记设置 availableDays，任务对孩子不可见
→ **缓解**: 家长端显示"待安排"状态标记，提醒家长

**风险**: 孩子不理解为什么某些任务不能做
→ **缓解**: 点击时明确提示"这个任务周三才能做哦"

**权衡**: 不支持复杂日期规则（如隔周二）
→ **接受**: 当前需求为每周固定日期，复杂规则暂不实现

4. 家长手动设置现有任务
